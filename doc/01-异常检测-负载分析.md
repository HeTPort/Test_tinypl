# 异常检测（AD01）负载设计分析

## 设计目标与定位

该负载面向已提取好的声学直方图或频谱特征，按短窗口做异常评分。仓库提供了输入形状、模型符号和 MLPerf Tiny 风格的设备协议；具体网络结构、模型权重以及设备端 `th_infer()` 不在当前代码树中。因此，下图中的“模型推理”是接口约定，而非本仓库可独立运行的完整实现。

```mermaid
flowchart LR
    A[特征文件及真值 CSV] --> B[runner 按长度与步长切重叠片段]
    B --> C[UART db load / db 十六进制传输]
    C --> D[设备端 5 × 128 特征窗口]
    D --> E[th_load_tensor → th_infer]
    E --> F[m-results 异常评分]
    F --> G[按文件聚合、阈值评估]
```

## 核心思路

1. **短窗口输入。** 配置将单次输入定为 5 个特征切片、每片 128 个元素，即 640 个特征值；另有 200 个频谱切片的常量，暗示原始样本包含更长的时间序列。设备侧 `MAX_DB_INPUT_SIZE` 写为 `5 × 128 × 4 × 2 = 5120` 字节，注释称 float32 直方图窗口；它是通信缓冲区上限，不能据此推断模型输入一定占满 5120 字节。[特征设置](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/anomaly_detection/micro_model_settings.h#L20-L27)、[设备接口](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/anomaly_detection/submitter_implemented.h#L29-L58)
2. **窗口在主机端生成。** `runner` 读取真值 CSV 中的 `bytes_to_send` 和 `stride`，以字节为单位滑动切片；准确率模式遍历片段，性能及能耗模式只取首片。这样设备只需接收固定长度的输入，不承担完整音频预处理。[切片逻辑](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/runner/script.py#L70-L119)、[数据集读取](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/runner/datasets.py#L14-L43)
3. **统一推理与计时。** 主机先以 `db load` / `db` 填充设备缓冲区，再发 `infer N W`。设备框架先调用 `th_load_tensor()`，执行 W 次预热，只对之后的 N 次推理打时间戳，最后调用 `th_results()`。这把输入传输与计时段分开，便于比较推理吞吐量。[设备推理框架](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/api/internally_implemented.cpp#L175-L191)、[主机协议](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/runner/device_under_test.py#L89-L107)

## 输出与评价

主机将同一文件的多个窗口结果归并。单值输出走逐阈值扫描的异常检测分支；该分支计算 `precision` 与 `recall` 的平均值并称为 `accuracy`，它不是标准 F1。通用汇总还会计算 AUC。由于单值窗口使用 `argmax` 做多数票时恒为第 0 类，且单值输出进入 AUC 汇总代码的路径未见专门处理，报告数值需结合真实数据复核。[指标实现](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/runner/main.py#L128-L154)、[结果汇总](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/runner/main.py#L255-L325)

## 可见边界

`model.h` 只声明 `g_model`，负载目录没有模型数组定义和异常检测专用推理实现；特征生成方法、模型层次、量化方式和实际阈值均无法从本仓库确认。[模型声明](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/anomaly_detection/model.h#L19-L26)
