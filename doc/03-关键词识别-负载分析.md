# 关键词识别（KWS01）负载设计分析

## 设计目标与定位

该负载对已经转换为固定形状的语音特征做 12 类分类。它是按样本触发的离线推理路径：输入特征由主机加载，设备执行一次或多次模型推理；仓库没有展示从原始 PCM 到该特征张量的提取流程。

```mermaid
flowchart LR
    A[语音特征文件 49 × 10 × 1] --> B[runner 读取与 db 传输]
    B --> C[设备输入张量 490 个 int8]
    C --> D[th_load_tensor → th_infer]
    D --> E[12 类输出向量]
    E --> F[类别索引 / Top-1 / AUC]
```

## 核心思路

1. **预先约定特征形状。** 配置将输入写为 49 行、10 列、单通道，共 490 个元素；测试输入声明为 `int8_t`，设备通信缓冲上限也为 490 字节。这让设备无需在推理时接收完整音频，但训练与测试必须使用一致的特征计算和量化规则。[形状设置](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/keyword_spotting/kws_model_settings.h#L19-L27)、[输入声明](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/keyword_spotting/kws_input_data.h#L16-L23)、[设备接口](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/keyword_spotting/submitter_implemented.h#L30-L57)
2. **类别边界明确。** 12 类中有 10 个命令词（down、go、left、no、off、on、right、stop、up、yes），另有 `silence` 和 `unknown`，用于把静音及非目标词与命令词分开。分类标签由输出索引决定，输出概率的产生方式取决于未提供的模型实现。[类别定义](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/keyword_spotting/kws_model_settings.cc#L16-L21)
3. **复用通用测量协议。** `runner` 根据设备报告的 `kws01` 选择测试脚本和数据集；`download` 将特征文件分批编码成十六进制，`infer N W` 先预热再测量。结果是 `m-results-[...]` 向量，主机据此计算 Top-1、AUC 和吞吐量。该设计将准确率、性能、能耗三种测试模式放在同一设备接口上。[负载选择](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/runner/main.py#L75-L88)、[传输与解析](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/runner/device_under_test.py#L89-L107)、[结果解析](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/runner/script.py#L235-L260)

## 可见边界

`kws_model_data.h` 只有模型数组声明。仓库没有声学前端、训练配置、模型层结构或 `th_*` 的具体实现；`kws_model_settings.cc` 的文件注释仍写着 visual wakewords，属于复用模板留下的注释，不能当作该负载的功能描述。[模型声明](https://github.com/HeTPort/Test_tinypl/blob/2eefac5b64a957133cb6b997dfa3949a401a68c7/keyword_spotting/kws_model_data.h#L1-L8)
